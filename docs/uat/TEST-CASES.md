# Gather UAT 用例清单

状态含义：`已自动化` 表示已有可执行断言；`需账号/数据` 表示框架已就绪，但首轮因本地凭据或安全的 UAT 数据缺失尚未取得产品结果。

| 编号 | 层级 | 场景 | 关键断言 | 当前状态 |
|---|---|---|---|---|
| AUTH-01 | smoke | 受保护路由 | 未登录跳转登录页 | 已自动化、首轮通过 |
| AUTH-02 | smoke | 错误凭据 | 保持登录页并展示错误 | 已自动化、首轮通过 |
| AUTH-03 | smoke | 登录与退出 | 有效账号进工作台，退出后路由受保护 | 已自动化、需账号 |
| PERM-01 | smoke | admin 菜单/路由 | 可见小组、分析、权限管理 | 已自动化、需账号 |
| PERM-02 | smoke | manager 菜单/路由 | 可见分析，不可见 admin 专属页 | 已自动化、需账号 |
| PERM-03 | smoke | user 菜单/路由 | admin/manager 专属页重定向 | 已自动化、需账号 |
| SCOPE-01 | full | 默认任务范围 | admin=全部，manager=我的小组，user=我的任务 | 已自动化、需账号 |
| CORE-01 | smoke | 开发人员 | 创建入口与必填校验，不落空数据 | 已自动化、需 admin |
| CORE-02 | smoke | 小组 | 运行前识别既有 UAT 小组；创建必填校验 | 已自动化、需 admin |
| CORE-03 | smoke | 项目 | 运行前识别既有 UAT 项目；创建必填校验 | 已自动化、需 admin |
| TASK-01 | full | 任务创建 | 标题/项目/负责人/日期必填 | 已自动化、需账号 |
| TASK-02 | full | 状态流转 | 待办→开始→提交审核→批准/驳回 | 已自动化，唯一命名 UAT 数据，需四类账号 |
| TASK-03 | full | 审批边界 | 只认项目负责人；测试组长不因此获得审批权 | 已自动化，需四个不同账号 |
| TEST-01 | smoke | 测试中心导航 | 测试计划、测试建设、资源汇总可达 | 已自动化、需测试工程师 |
| TEST-02 | smoke | 外部测试 | 必填校验；不创建空计划 | 已自动化、需测试工程师 |
| TEST-03 | full | 内部候选项目 | 仅本人负责、已审批且未覆盖的开发任务可纳入；非负责人被拒绝 | 已自动化，复用任务流转 UAT 数据 |
| TEST-04 | full | 排期与活动拆分 | 测试组长确认排期，拆分系统测试活动 | 已自动化，需测试组长和测试工程师 |
| TEST-05 | full | 执行批次 | 中文测试类型、环境/版本/数量、实际工时 | 已自动化，唯一 UAT 外部计划 |
| TEST-06 | full | 结构化结论 | 各字段必填；测试组长退回、再提交、批准 | 已自动化；最终批准被 `UAT-DEFECT-002` 阻塞 |
| TEST-07 | full | 测试建设 | 自动化工程师创建、排期、拆分、50% 进度、工时、成果确认 | 已自动化；定向复测通过 |
| TEST-08 | smoke/full | 资源汇总 | 三来源工时及合计、人员冲突口径 | 已自动化、需测试账号 |
| UI-01 | full | 日期控件 | 圆角/高度/弹层样式可用 | 已自动化、需 admin |
| UI-02 | full | 弹窗一致性 | 统一圆角、阴影、标题与滚动容器 | 已自动化、需 admin |
| UI-03 | full | 中文测试类型 | 冒烟/系统/回归/性能/兼容/安全中文展示 | 数据驱动场景 |
| UI-04 | full | 工时展示 | 项目实际投入与三来源资源工时口径 | 已自动化；建设详情顶部汇总存在 `UAT-DEFECT-003` |
| RLS-01 | full | user 创建小组越权 | 服务端返回 RLS 拒绝，数据不落库 | 已自动化、需 user |
| RLS-02 | full | user 更新他人任务 | admin 创建唯一 `UAT-RLS-*` 目标；user 更新返回空；admin 复核未改变 | 已自动化；定向复测通过 |
| RLS-03 | full | 审批越权 | 非项目负责人不能批准/驳回 | 需项目负责人、非负责人及 review 任务 |
| SAFE-01 | smoke | 敏感字段 | 页面不展示 Authorization/JWT/anon key | 已自动化、首轮通过 |

首轮真实分角色执行前，应先确认本地 `.env.uat` 的业务身份映射，并检查已有 `UAT-质量保障组`、`UAT-研发组`、`UAT-全流程验收项目` 是否满足关系与状态前置条件。
