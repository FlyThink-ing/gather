该目录仅用于需求演示，不属于正式应用源码，不读取或写入 Supabase。

## 完整演示顺序

1. 以“项目负责人”进入测试计划，提交项目总体测试计划。
2. 切换“测试组长”，进入测试排期队列，接受计划并确认窗口与默认主测试人。
3. 切换“项目负责人”，在项目驾驶舱发起 V2.0 项目提测，观察默认范围、范围快照和准入阻断项。
4. 切换“测试组长”，在队列接受轮次，确认本轮时间、主测试负责人和参与人员。
5. 切换“主测试负责人”，在轮次详情开始、暂停、恢复测试。
6. 提交“通过”或“不通过”结论，确认状态只进入 `conclusion_pending`。
7. 切换“测试组长”，确认结论或退回补充。
8. 不通过时进入修复页面：项目负责人创建/关联具体修复任务、模拟审批完成，再发起下一轮测试。
9. 通过时进入完成确认：项目负责人核对全部条件和遗留风险，最终完成项目。
10. 在项目驾驶舱查看多轮记录；展开“历史单任务测试”，确认其来源和统计口径独立。

## 权限验证

- 项目负责人：测试计划、发起提测、修复闭环、项目完成。
- 测试组长：计划/轮次接单、排期、人员、确认或退回结论。
- 主测试负责人：开始、暂停、恢复、提交结论。
- 参与测试人员：只读整轮状态，无最终结论按钮。
- 部门经理：只读风险和排期，无接单、执行或确认按钮。
