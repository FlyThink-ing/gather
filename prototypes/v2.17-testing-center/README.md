# v2.18 测试中心、测试建设与测试资源交互原型

该目录用于第十七、十八章及 D20–D29 的需求演示，不属于正式应用源码，不连接 Supabase，也不读取或写入生产数据。目录名称沿用 v2.17-testing-center，但页面内容已经升级到 v2.18；旧版 v2.16-project-testing 原型保持不变。

## 打开方式

直接用浏览器打开 index.html。

如本地浏览器限制脚本，可在项目根目录使用 Python 启动静态服务，将目录指向 prototypes/v2.17-testing-center，并访问 http://localhost:4175/。

## 推荐演示路径

1. 以“测试组长”打开测试计划列表，用来源筛选比较“内部项目/外部独立”，确认它们共用状态、接单、排期和资源口径。
2. 新建外部独立测试，验证只填写外部项目名称、项目负责人、版本、范围、窗口、环境、优先级、交付物和相关链接；项目负责人仅为责任归属文本，不要求注册或登录。
3. 打开内部项目计划，切到“项目负责人”提交自由文本“无需测试原因”；切回“测试组长”同意或驳回。未确认或驳回时仍按需要测试。
4. 测试组长接单，在“活动与排期”查看冒烟、系统、回归、性能活动及每人计划/实际投入；新增一个活动。
5. 切到“主测试负责人”或“参与测试人员”，在“执行批次”录入一次批次；故意让分类数之和不等于实际执行数，观察校验，再修正并查看自动汇总。
6. 在“报告与结论”选择系统/性能报告的“已出具”或“未出具”；只有未出具时出现并校验说明。页面不提供报告文件、链接、版本或编写人字段。
7. 主测试负责人提交后状态仅到“待测试组长确认”；切到“测试组长”确认或退回补充。外部计划也不要求外部项目负责人登录审批。
8. 在“测试资源”查看每人内部/外部来源、对应项目负责人、计划/实际/剩余、冲突、阻断与偏差；确认页面没有排名或绩效评分。
9. 打开“项目驾驶舱”，确认只显示内部项目测试摘要，外部独立计划不出现，并可跳回统一测试中心。

## v2.18 测试建设演示路径

1. 切换“自动化测试人员 · 刘洋”，打开“测试建设”，确认它与“测试计划”并列，并使用建设类型、负责人、状态、优先级和日期筛选。
2. 新建测试建设工作，填写目标、每人计划工时、交付成果、完成标准、仓库/文档/流水线及风险；保存后进入草稿详情。
3. 自动化测试人员提交排期；切换“测试组长”确认优先级、人员、时间和投入后进入进行中。
4. 在详情拆分建设任务，切回自动化测试人员或参与人员记录实际工时，观察计划/实际投入和整体进度变化。
5. 自动化测试人员填写完成说明并提交成果确认；测试组长确认完成或退回补充。项目负责人视角没有排期或成果确认操作。
6. 对进行中工作执行暂停或取消，验证原因必填；打开已暂停演示项可执行恢复。
7. 打开“测试资源”，按“测试建设工作”筛选，查看刘洋的 56h 建设占用、2h 剩余容量、同期项目测试占用与风险；从资源行跳转建设详情。
8. 确认资源汇总分为内部项目测试、外部独立测试、测试建设工作三种来源，并明确建设投入不计入项目测试成本。
9. 打开项目驾驶舱，确认测试建设工作不出现。

## 权限核对

- 项目负责人：本人项目内部测试资料、无需测试申请、项目驾驶舱；不能接单、排期、确认测试结论。
- 测试组长：全部计划接单排期、活动与报告要求、资源安排、结论确认/退回。
- 主测试负责人：执行批次、整轮结构化结论、报告出具状态及未出具说明、提交结论；不能自行确认。
- 参与测试人员：本人授权活动的执行批次；不能提交整轮结论。
- 部门经理：只读摘要，不因身份自动获得测试操作。
- 自动化测试人员：创建、拆分、执行测试建设工作，记录实际投入并提交成果；不能自行确认排期或最终完成。
- 测试组长（测试建设）：确认优先级、排期、资源和最终成果，不经过项目负责人审批。
